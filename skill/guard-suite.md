# 一键体检（dsh-guard-suite）

**什么时候用**：想一次性看清一个项目在合规/安全上有哪些问题、分在哪些块。
用户会说：「帮我整体体检一下」「我装了这么多检查插件，能不能一次跑完」「给我一份能直接看的检查报告」
「上线前想统一扫一遍」「按模块告诉我哪里有问题」。

## 怎么用

```bash
<cli 路径> --list-plugins              # 先看发现到了哪些插件（确认"装全了没"）
<cli 路径> --root <项目目录>            # 跑到你的项目上
<cli 路径> --root <项目目录> --json     # JSON（给 CI、给 dsh-compliance-doc 生成文档）
<cli 路径> --root <项目目录> --html 体检.html
<cli 路径> --demo                      # 看报告格式
```

常用过滤：

```bash
<cli 路径> --only cn-mlps,cn-log-retention    # 只跑这两块
<cli 路径> --skip cn-crypto                    # 跳过某块
<cli 路径> --fail-on medium                    # CI 里更严的卡口（默认 high）
```

## 它是什么、不是什么

**是**：体检编排器。把你已经装好的守卫插件规则集合起来，**一次扫描、一份分组报告**。
**不是**：新的判据库。它自己一条规则都没有 —— 判据全部来自各个插件，找到几条跑几条。

## 它怎么找到插件

按顺序找，找到哪个用哪个（**不联网、不下载**）：

1. `--rules-from <目录>` 指定的目录（给了就只用这些，便于可复现）
2. 与本插件同级的 `dsh-*` 目录
3. `node_modules/@deepwhale-cn/dsh-*`
4. 环境变量 `DSH_GUARD_PLUGINS`（冒号分隔）

**一个都没找到时**：直接报错退出（exit 2），并列出搜过哪些路径。
这一步是故意做"硬"的 —— 「0 命中」和「一条规则都没跑」在终端上长得一模一样，
不报错就一定会被当成"项目很干净"。

## 报告怎么读

- **报告头**：扫了多少文件、发现几个插件、几条规则、几条因不适用没跑 —— 先证明"确实查了"。
- **按插件**：每一块单独一行，0 命中也显示（否则分不清"查了没问题"和"没查"）。
- **不适用**：本项目没触发条件的规则单独列出，不算"查过了"。
- **明细**：按严重度铺开，每条带文件:行、依据、怎么办。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 没有达到 `--fail-on` 的命中 |
| 1 | 有达到阈值的命中（可挂 CI） |
| 2 | 参数错误，或一个插件规则都没发现（**不当作全绿**） |

## 它不做什么

- 不联网、不上传代码、不下载规则。
- 不判定"合规/不合规"，只报事实 + 依据，供你确认。
- 不替代等保测评、监管检查或第三方审计。
